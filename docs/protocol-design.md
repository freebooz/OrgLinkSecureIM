# 即时通信协议设计

## 分层

```text
TCP stream
└── 68-byte fixed transport header (network byte order)
    └── optional header extensions in a future version
        └── Protobuf message body
            └── domain payload / encrypted content
```

TLS/TLCP 保护整条连接。应用层仍保留请求幂等、时间窗、序列和内容加密标志，因为传输安全不能替代可靠投递与存储安全。

## 固定头布局

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 4 | magic | ASCII `OLIM` |
| 4 | 2 | version | 当前 1 |
| 6 | 2 | header_size | 当前 68，未来扩展头长度 |
| 8 | 2 | message_type | `common.proto` 中稳定枚举 |
| 10 | 2 | flags | encrypted/compressed/ack-required |
| 12 | 8 | request_id | 请求响应关联，0 表示单向事件 |
| 20 | 8 | session_id | 认证会话；服务端仍以连接上下文为准 |
| 28 | 8 | user_id | 登录账号标识，不代替 PersonId |
| 36 | 8 | device_id | 登录设备标识 |
| 44 | 8 | timestamp_utc_ms | 防重放时间窗和诊断 |
| 52 | 8 | sequence | 连接/会话语义序列，由消息类型定义 |
| 60 | 4 | body_length | 最大 16 MiB，超限在分配前拒绝 |
| 64 | 4 | checksum | body CRC32，仅传输差错检测 |

实现位于 `libs/protocol/include/orglink/protocol/Frame.h` 和 `src/Frame.cpp`。扩展字段通过增加 header_size 和尾随 TLV 演进；当前实现遇到非 68 长度时安全拒绝，待 TLV 规范落地再开放。

## 消息类别

- 1000：登录、退出、心跳。
- 2000：单聊、群聊、接受/送达/已读、撤回、离线同步。
- 3000：在线状态。
- 4000：文件申请、分片、下载、进度和完成。
- 5000：组织快照/增量、部门人员、搜索、详情、收藏、唯一单聊、选人建群。
- 6000：群组、通知、设置与通讯录个人化；`6101`～`6110` 承载群列表、详情、创建、加入和成员变更，`6201`～`6208` 承载通知列表、详情、状态动作和分类全部已读，`6301`～`6306` 承载设置读取、完整快照更新和恢复默认，`6401`～`6406` 承载通讯录摘要、联系人详情和个人偏好更新。
- 9000：统一错误响应。

线上枚举只新增不改值；删除字段在 Proto 中 `reserved`，客户端必须保留未知字段转发能力并忽略未知可选字段。

通讯录协议不接受客户端提交 owner PersonId：Gateway 始终使用认证连接中的人员身份。`6401/6402` 返回最近与收藏摘要，`6403/6404` 返回权限裁剪后的详情、共同群组和当前偏好 revision，`6405/6406` 使用期望 revision 更新收藏、标签和私有备注；版本冲突返回 `64009`，由客户端重新读取详情后再提交。

## 编解码

发送：验证字段 → Protobuf 序列化 → 可选压缩 → 可选内容加密 → 计算体 CRC → 网络序写头 → 单写队列发送。接收：读缓冲 → 检查 magic/version/header/长度 → 等待完整体 → CRC → 解密 → 解压 → 按 message_type 解析 Proto → 语义校验 → 路由。

每条连接只允许一个写序列器，多个业务线程提交到有界 MPSC 队列，避免 TCP 字节交错。解码器属于连接，不跨线程共享；断线后清空残包。

## 心跳与重连

- 空闲 15 秒发送 PING，PONG 携带服务端时间和最新会话状态。
- 5 秒无响应记一次失败，连续 3 次关闭连接。
- 重连采用 1、2、4、8、16、30 秒上限的指数退避并加入 ±10% 抖动。
- 重连成功后先恢复认证与同步水位，再重发 SQLite Pending；使用原 client_message_id。
- 系统时间偏差超过策略阈值时拒绝高风险请求并提示时间同步，不自动放宽防重放窗口。

## 幂等、顺序和超时

- 请求幂等：RequestContext.idempotency_key；服务端存储响应摘要和有效期。
- 消息幂等：唯一键 `(sender_device_id, client_message_id)`。
- 会话顺序：服务端原子分配 `(conversation_id, sequence)`。
- 接收去重：server_message_id 和已提交连续水位。
- 小范围乱序进入有限 reorder buffer；发现缺口请求 `[from,to]`，超阈值走分页同步。
- 超时只表示“结果未知”，不能生成新幂等键盲目重做。

## 错误码

32 位错误码建议 `模块(8) | 类别(8) | 细项(16)`：

| 范围 | 模块 | 示例 |
|---|---|---|
| `0x01xxxxxx` | 通用/协议 | 版本不支持、帧过大、限流 |
| `0x02xxxxxx` | 认证 | 凭据错误、锁定、令牌过期 |
| `0x03xxxxxx` | 目录 | 人员不可见、修订失效 |
| `0x04xxxxxx` | 会话/群组 | 非成员、已解散、成员上限 |
| `0x05xxxxxx` | 消息 | 重复但可返回原结果、撤回超时 |
| `0x06xxxxxx` | 文件 | 类型拒绝、配额、校验/扫描失败 |
| `0x07xxxxxx` | 安全 | 证书过期、签名失败、重放 |
| `0x08xxxxxx` | 运维 | 服务不可用、版本过低 |

客户端只展示 `message_key` 本地化文本和 correlation_id；数据库错误、路径、堆栈和内部节点不得返回。

## 限流和背压

连接帧率、账号消息率、IP 登录率、会话突发、文件字节率分别使用令牌桶；全局写队列达到高水位后暂停 socket 读或返回 retry_after。心跳和安全通知保留独立小配额，不能被文件/聊天洪泛饿死。

## 当前验证

已用真实字节和双客户端验证编码、半包/粘包、CRC、TLS 登录、心跳、目录全量/增量、单聊、群组创建/列表/详情、成员管理、群聊扇出、通知列表/详情/状态审计、会话列表/历史、ACK、推送、`2011` 送达回执、`2012` 已读回执、文件上传下载授权和会议加入/离开。文件正文单次上限 8 MiB，服务端重新计算 SHA-256 后才写入私有对象存储；通知附件通过同一下载协议按通知接收人二次鉴权。会议响应只返回短期 JWT 和可访问 URL，不持久化令牌。群消息对每个有效接收成员建立独立 Outbox，复合幂等键为 `(message_id, recipient_person_id)`。回执采用会话连续序号水位，由服务端验证接收方身份与锚点后只路由给原发送方。目录增量使用 `5003/5004`，连续覆盖 `(from_revision, current_revision]`，单批最多 500 条；断档、硬删除、未知类型或跨度过大返回 `full_snapshot_required`。轻量 codec 与 `.proto` 字段保持一致，但 protoc 生成、TLCP、协议 fuzz 和大文件分片仍未完成。
